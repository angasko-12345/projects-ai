## Changes made

### ROOT-014 — resume crash on a finished checkpoint — FIXED

`training/ppo.py` gained `PPOTrainer.is_complete()`; `train()` returns early when the checkpoint
already met `total_timesteps`, prints the step count and budget, states that no updates will run,
and keeps the existing `ppo_final.pt` — still writing one if it is absent, preserving the
"always leaves a final checkpoint" contract.

A new `summarize_history()` is the single reader for history aggregates and tolerates the empty
history. `main.py` and `training/experiment.py` both use it, so nothing indexes `history[...][-1]`
unguarded.

`experiments/*_results.json` gained a `training_updates` field so a run that trained nothing is
visible in the artifact rather than reading as a measured zero reward.

Exit code is **0** for a no-op resume, on the reasoning that the requested end state already
exists; the message states how to continue. Regression tests cover exactly-complete,
over-complete, and normal resume, using a real trainer rather than a mock.

### ROOT-036 — eval hit/miss metric — FIXED as a contract clarification

**Not a reward-semantics change.** The command was always intended to support arbitrary reward
providers; hit/miss was the unstated assumption. Semantics are now *declared* rather than inferred:

- `environment/reward.py` defines `SIGN_SEMANTICS` / `GENERIC_SEMANTICS` and a
  `reward_semantics_of()` reader that **fails closed**: an undeclared or unrecognised declaration
  becomes `generic`, with a warning and never an exception, so a bad declaration cannot destroy a
  multi-hour run at reporting time.
- `RewardProvider` defaults to `generic`. Only `ToyPongEnv` and `ExternPongReward` declare `sign`.
- `ExternalGameEnv` exposes `reward_semantics` as a **property**, not an `__init__` snapshot,
  because callers and tests swap `reward_provider` after construction and a stale value would
  republish hit counts for rewards that no longer mean that.
- `evaluate()` reports `episode_hits` / `episode_misses` / `mean_hits` / `mean_misses` **only**
  when semantics are `sign`; otherwise those keys are **omitted entirely**. Absence rather than
  `0.0`, because `0.0` reads as "hit nothing". The counts remain available under
  `episode_positive_reward_steps` / `mean_negative_reward_steps`.
- `PreprocessingWrapper` downgrades to `generic` when `skip > 1`, because summing rewards across
  frames breaks the one-event-per-decision-step invariant.
- Consumers became conditional: `main._print_eval_report`, and `summarize_eval` /
  `summarize_difference` in `training/external_experiment.py`. Metrics are now derived from the
  summaries rather than a second hand-maintained list; mismatched sides report
  `reward_semantics: "mixed"`.
- `METRIC_DEFINITIONS` gained `reward_semantics`, `mean_hits`, `mean_misses`.

**No** reward semantics, PPO mathematics, or tracked `experiments/*_results.json` were changed.

### ROOT-011 — DOCUMENTED, no code change

The capture output-size contract is now stated in `make_external_env_from_config`:

- `capture.out_width` / `out_height` are honoured only by `synthetic`;
- `region` returns the captured rectangle, defaulting to the out size only when
  `capture.region.width` / `height` are absent;
- `window` returns the native window rect.

Native frames are deliberate: the reward/termination detectors are red-pixel-count bands that
only separate a 6 px ball from a MISS banner on undownscaled frames. Recorded as a contract
decision, not a resize bug.

## Design review before implementation

An independent read-only reviewer reviewed the proposed ROOT-036 contract before any code was
written and returned **six concrete failure modes** in the proposal, of which **three would have
broken the test suite** and **one would have reintroduced the exact lie the change existed to
remove** (a snapshot `reward_semantics` that goes stale when a provider is swapped). Two were
unlisted consumers the proposal had missed.

Its conclusions were adopted, including: "declare on the `RewardProvider` ABC", "property not
snapshot", "downgrade on `skip > 1`", and "derive comparison metrics instead of hand-maintaining a
second list".

### Step-3 external Pong pre-flight

Real window, real screen capture, real `SendInput`, 240 decision steps through the real external
path.

- Native frame is **279x336** (the 320x240 canvas plus window chrome).
- Red-pixel counts showed **0 steps in the ambiguous 200..300 gap**.
- The MISS banner band (`>=300`) matched the number of misses exactly (**7 banners / 7 misses**).
- No window-chrome red above the hit band.
- Counts of 1..7 red pixels do occur (**23 steps**) but sit **below** `hit_min=8`, so they classify
  as "normal" and cannot manufacture a false hit; a later in-band frame still pays the rising-edge
  +1.
- `env.reward_semantics` correctly reports `"sign"` for this provider.

### Caveat recorded for anyone reading exp02 hit counts

The exp01/exp02 decision cadence (60 ms key hold + 80 ms post-action delay) moves the paddle
5 px per decision while the ball travels roughly 34 px in the same time. A pixel-chase policy
therefore scored only about **2 hits per 7 misses**. Low hit yield is that cadence, not detector
loss.
